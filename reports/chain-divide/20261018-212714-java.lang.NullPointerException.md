**Summary.** A NullPointerException occurred at line 84 of `ChainDivide.java` due to an attempt to invoke `.toUpperCase()` on a null String. The root cause was identified as a race condition where concurrent executions computed keys (9 or 6) that lacked corresponding entries in the shared `labels` map.

## Root cause hypothesis
The incident stems from a race condition/timing issue during concurrent execution:
1. The `loadConfig()` method populates the `labels` map by reading `config/chain-divide.properties`.
2. Multiple runs execute concurrently and share the same `ChainDivide` instance (same `labels` map).
3. When run 4 (`[81, 9]`) computes `chainDivide([81, 9]) = 81 / 9 = 9`, it attempts to look up label key 9.
4. The labels map was populated before any of these runs started (in `runInParallel()` at line 37).
5. Different sets produce different keys, and some keys may not have corresponding labels defined in the config file.

## Suggested fix
Handle the case where `labels.get(key)` returns null by either providing a default value or throwing an exception:
Option A (Default Value):
```java
String name = labels.get(key);
String label = (name != null) ? name.toUpperCase() : "UNKNOWN";
log.info("label.found", "Label: " + label, "key", key, "label", label);
return label;
```
Option B (Validation):
```java
String name = labels.get(key);
if (name == null) {
    log.error("label.missing", "No label found for key {}", key);
    throw new RuntimeException("Label not found");
}
String label = name.toUpperCase();
```
